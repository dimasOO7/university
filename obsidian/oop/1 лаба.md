## 1. Три направления развития платформы Java.
1. **J2SE / Java SE (Java Standard Edition)** — стандартная редакция:
    
      
    - Ориентирована преимущественно на персональные компьютеры и рабочие станции.
        
          
        
    - Включает базовые библиотеки и среду выполнения; именно эту платформу обычно имеют в виду, когда говорят о базовом языке Java или JDK.
        
          
        
2. **J2EE / Java EE (Java Enterprise Edition)** — корпоративная редакция:
    
      
    - Специально предназначена для создания сложных распределённых систем и приложений уровня предприятия.
        
          
        
    - Предоставляемая среда разработки и API позволяют проектировать как независимые масштабируемые системы, так и решения, ориентированные на работу через web-интерфейсы.
        
          
        
3. **J2ME / Java ME (Java Micro Edition)** — микроредакция:
    
      
    - Ориентирована на встроенные решения и программное обеспечение для специализированных пользовательских цифровых устройств (мобильных телефонов, портативной техники, пультов и т. д.).
        
          
        
    - Разработчику в рамках этой платформы предоставляется минимально необходимый объём API для работы в условиях ограниченных аппаратных ресурсов.
        
          
        

Позже, начиная с версии Java 1.5, произошёл отказ от обозначения «Java 2» и первой цифры в нумерации версий, после чего для направлений закрепились названия **Java SE**, **Java EE** и **Java ME**.

## 2. Характерные особенности языка Java.
- **Простота**: синтаксис языка изначально проектировался как упрощённый вариант синтаксиса C++. Из языка были исключены сложные и чреватые ошибками конструкции: отсутствуют явные указатели и адресная арифметика, нет деструкторов объектов, а управление памятью берёт на себя автоматическая «сборка мусора» (Garbage Collection).
    
      
    
- **Объектная ориентированность**: в центре внимания находятся объекты и их типы. Java является более строгим объектно-ориентированным языком, чем C++ или Object Pascal. Например, механизм множественного наследования классов заменён более стройной и безопасной концепцией интерфейсов.
    
      
    
- **Архитектурная независимость (кросс-платформенность)**: компилятор Java преобразует исходный код (.java) не в машинный код конкретного процессора, а в машинно-независимый байт-код (.class). Скомпилированная программа способна выполняться на любых аппаратных платформах и операционных системах, где установлена соответствующая виртуальная машина Java (JVM — _Java Virtual Machine_).
    
      
    
- **Переносимость**: в отличие от C и C++, ни один из аспектов спецификации языка не зависит от конкретной архитектуры компьютера. Размеры примитивных типов строго фиксированы (к примеру, тип `int` всегда занимает ровно 32 бита независимо от платформы). Бинарные данные хранятся и передаются в неизменном формате независимо от порядка байтов (endianness), а строковые данные поддерживают стандарт Unicode.
    
      
    
- **Надёжность**: повышенное внимание уделяется раннему обнаружению ошибок на этапе компиляции, строгому контролю типов и проверкам в процессе выполнения (например, контроль выхода за границы массива), а также развитому механизму обработки исключительных ситуаций.
    
      
    
- **Безопасность**: так как язык изначально создавался для работы в сетях, в него встроена гибкая настраиваемая система защиты среды выполнения. Она предотвращает намеренное переполнение стека, повреждение чужих участков оперативной памяти, а также несанкционированный доступ к файловой системе.
    
      
    
- **Распределённость**: в платформу изначально заложены широкие возможности для создания сетевых и распределённых приложений. Это включает как низкоуровневые средства работы с сетевыми протоколами TCP/UDP (сокеты), так и высокоуровневые API (работа с HTTP через класс `URL`), а также технологию удалённого вызова методов RMI (_Remote Method Invocation_).
    
      
    
- **Многопоточность**: язык имеет встроенные языковые конструкции и библиотеки для организации параллельных вычислений и многопоточной синхронизации, что обеспечивает высокую производительность в реальном времени и удобно для серверных систем.
    
      
    
- **Динамичность**: программы на Java динамически связываются и подгружают необходимые классы во время выполнения, что позволяет расширять возможности программ без их полной перекомпиляции.
    
      
    
## 3. Три принципа ООП. Пример.
- **Инкапсуляция**
    
    - **Определение:** Это объединение данных (полей) и методов их обработки в одну сущность, имеющую чёткие границы.
        
    - **Суть:** Инкапсуляция обеспечивает сокрытие внутренней реализации класса и отделение его внутреннего представления от внешнего.
        
    - **Как достигается в Java:** Поля данных объявляются закрытыми (`private`), предотвращая несанкционированное вмешательство извне, а доступ к ним и их изменение осуществляются через открытые контрактные методы (`public` геттеры и сеттеры).
        
- **Наследование**
    
    - **Определение:** Отношение между классами, при котором один класс (производный, _subclass_) использует структуру и поведение другого (базового, _superclass_).
        
    - **Суть:** Наследование позволяет строить иерархии типов и обеспечивает повторное использование кода. Класс-наследник расширяет (`extends`) функциональность родительского класса, добавляя новые поля и методы или переопределяя существующие.
        
- **Полиморфизм** (буквально _«множественность формы»_)
    
    - **Определение:** Способность объекта соответствовать во время выполнения двум или более возможным типам.
        
    - **Суть:** Объект производного класса может выступать в качестве экземпляра любого из своих родительских типов. При вызове переопределённого метода через ссылку базового типа выбор конкретной реализации определяется **фактическим классом объекта во время выполнения**, а не типом переменной-ссылки.

## 4. Достоинства и недостатки ООП.
### **Достоинства ООП**

  

1. **Упрощение разработки:**
    
      
    
      
    - **Разделение функциональности:** Чем сложнее и больше система, тем важнее делить её на небольшие, четко очерченные части. Классы служат удобным инструментом для абстрагирования от мелких деталей.
        
          
        
    - **Локализация кода:** Данные и инструкции по их обработке объединены в одной сущности и не разносятся по всей программе (как это часто бывает в процедурном подходе), что повышает наглядность и облегчает сопровождение ПО.
        
          
        
    - **Инкапсуляция:** Обеспечивает модульность кода, упрощая распределение задач между несколькими разработчиками и обновление версий отдельных компонентов.
        
          
        
2. **Возможность создания легко расширяемых систем:**
    
      
    
      
    - **Обработка разнородных структур данных:** За счет полиморфизма программы способны единообразно работать с объектами разных видов, существенно упрощая код; новые типы объектов можно добавлять в систему в любой момент.
        
          
        
    - **Изменение поведения на этапе выполнения:** Динамическое связывание позволяет «на лету» подменять один объект другим, изменяя поведение и даже алгоритмы программы во время работы.
        
          
        
    - **Полиморфизм и программирование в соответствии с типом:** Если обращаться к объектам только через методы типа переменной (контракт), то с помощью наследования и полиморфизма можно расширять функционал локально, не переписывая основную часть существующего кода.
        
          
        

### **Недостатки ООП**

  

1. **Неэффективность на этапе выполнения:**
    
      
    
      
    - Принцип инкапсуляции требует скрывать прямой доступ к полям и обращаться к ним через методы (геттеры/сеттеры), что порождает накладные расходы на процедурный вызов при каждом чтении или записи данных.
        
          
        
    - Прямой доступ к полям объекта также может требовать больших затрат ресурсов, чем обращение к локальным переменным.
        
          
        
2. **Неэффективность в смысле распределения памяти:**
    
      
    
      
    - Для поддержки динамического связывания и проверки типов в рантайме требуется информация о типе. Под неё выделяется дескриптор типа (один на класс), а каждый объект хранит специальный указатель на дескриптор своего класса, что увеличивает расход памяти.
        
          
        
3. **Излишняя избыточность:**
    
      
    
      
    - Библиотечные классы часто содержат больше методов, чем требуется для конкретной задачи. Удалить их нельзя, поэтому они ложатся «мертвым грузом», увеличивая итоговый объем кода и время разработки.
        
          
        
4. **Психологическая сложность проектирования:**
    
      
    
      
    - Несмотря на то, что концепции ООП близки к реальному миру, программистам (особенно переходящим с процедурной парадигмы) бывает трудно перестроить мышление под объектную модель.
        
          
        
5. **Техническая сложность документирования и проектирования:**
    
      
    
      
    - Документировать классы сложнее, чем отдельные процедуры: необходимо описывать не только логику работы метода, но и контекст его вызова, а также цели переопределения (особенно для абстрактных методов).
        
          
        
    - Проектирование в виде системы классов ставит нетривиальные архитектурные задачи правильного распределения функциональности, определения иерархий и порядка взаимодействия объектов.

## 5. Классы и объекты. Свойства объектов. Пример.

Программы на языке Java создаются из классов. Класс представляет собой описание структуры и поведения, задающее новый ссылочный тип данных.

Основным же видом сущностей в работающей программе являются **объекты** (или **экземпляры класса**). Зная имя класса, программа может создать необходимое число его объектов.

Важно разделять понятия объектной ссылки и самого объекта:

- Объявление переменной ссылочного типа лишь создает переменную, способную хранить ссылку на экземпляр класса. Оно не создает сам объект в памяти.
    
- Сам объект должен быть создан явным образом, чаще всего с помощью оператора `new` и вызова конструктора. При этом исполняющая система выделяет память под поля объекта, инициализирует их и возвращает ссылку на созданный объект.
    

### 2. Свойства и базовые характеристики объектов

В объектно-ориентированном подходе и лекционном курсе по Java каждый объект характеризуется тремя базовыми свойствами:

- **Состояние объекта** — совокупность значений, описывающих данный объект. Состояние определяется его полями (переменными экземпляра). Каждый объект обладает собственными копиями нестатических полей и сохраняет информацию о своем текущем состоянии.
    
- **Поведение объекта** — набор действий, которые объект способен выполнять. Поведение определяется методами класса. Состояние объекта со временем может изменяться, но в соответствии с принципом инкапсуляции это должно происходить только в результате вызовов соответствующих методов.
    
- **Сущность (уникальность / идентичность) объекта** — свойство, позволяющее однозначно отличать конкретный объект среди других объектов того же класса, даже если их состояние (набор значений полей) и поведение полностью совпадают.
    

Кроме того, в контексте инкапсуляции в Java термином **«свойства» (properties)** называют характеристики объекта, управление доступом к которым осуществляется через методы чтения (`get...` / `is...`) и записи (`set...`), так называемые методы доступа (accessor methods).

## 6.Члены класса. Модификаторы объявления класса.
### 1. Члены класса (Members)

Класс может содержать члены трёх основных категорий:

  

- **Поля (fields)** — переменные, относящиеся к классу и его объектам и в совокупности определяющие состояние класса или конкретного объекта. Поля могут принадлежать отдельным экземплярам (переменные экземпляра) либо всему классу в целом, если они объявлены с модификатором `static` (переменные класса).
    
      
    
- **Методы (methods)** — именованные фрагменты исполняемого кода класса, обуславливающие особенности поведения объектов класса. Методы оперируют состоянием объекта и предоставляют интерфейс взаимодействия с ним.
    
      
    
- **Вложенные типы** — объявления классов или интерфейсов, размещённые внутри контекста объявлений других классов или интерфейсов.
    
      
    

Также в составе класса объявляются **конструкторы**. Они служат для инициализации создаваемых объектов, однако важно помнить: конструкторы не относятся к категории обычных методов и не наследуются производными классами.

  

### 2. Модификаторы объявления класса

Модификаторы указываются перед ключевым словом `class` и задают дополнительные свойства и правила использования создаваемого типа.

  

В объявлении классов верхнего уровня применяются следующие модификаторы:

  

- **`public`**:
    
      
    - Класс помечается признаком общедоступности.
        
          
        
    - Это означает, что в любом коде разрешено объявлять ссылки на объекты этого класса и обращаться к его доступным членам.
        
          
        
    - Если модификатор `public` не указан, класс имеет доступ по умолчанию (на уровне пакета) и будет доступен только классам из того же пакета.
        
          
        
    - В одном исходном файле (`.java`) не может содержаться более одного класса, объявленного как `public`, причём имя файла должно в точности совпадать с именем этого публичного класса.
        
          
        
- **`abstract`**:
    
      
    - Класс трактуется как неполный.
        
          
        
    - Создавать объекты (экземпляры) абстрактного класса с помощью оператора `new` запрещено.
        
          
        
    - Абстрактный класс служит базой для наследования и обычно содержит один или несколько абстрактных методов, реализацию которых обязаны предоставить конкретные классы-наследники.
        
          
        
- **`final`**:
    
      
    - Завершённый класс, который категорически запрещено расширять (наследовать).
        
          
        
    - Объявление класса как `final` часто используется из соображений безопасности и оптимизации.
        
          
        
    - Все методы такого класса косвенным образом также становятся финальными (их невозможно переопределить).
        
          
        
- **`strictfp`** (_strict floating point_):
    
      
    - Гарантирует, что все операции с плавающей запятой в методах данного класса выполняются строго и единообразно всеми виртуальными машинами Java (согласно стандарту IEEE-754).
        
          
        
    - Если данный модификатор не задан, JVM может использовать расширенную точность аппаратных средств конкретного процессора для ускорения вычислений, из-за чего результаты вычислений на разных платформах могут незначительно отличаться.
        
          
        

#### Важные правила комбинирования:

- Модификаторы **`final`** и **`abstract`** являются взаимоисключающими и **не могут** использоваться в объявлении одного и того же класса одновременно, так как абстрактный класс обязательно требует реализации в наследниках, а финальный класс запрещает наследование.
    
      
    
- Класс может содержать несколько допустимых модификаторов, при этом порядок их записи перед ключевым словом `class` значения не имеет.

## 7. Пакеты.

### 1. Понятие пакета и его назначение

**Пакет (package)** — это комплект программного обеспечения, который может распространяться независимо и применяться при разработке приложений в сочетании с другими пакетами.

  

Членами пакетов являются:

  

- взаимосвязанные классы;
    
      
    
- интерфейсы;
    
      
    
- вложенные пакеты;
    
      
    
- дополнительные файлы ресурсов (например, графические), используемые в коде классов.
    
      
    

Применение пакетов решает несколько ключевых задач:

  

1. **Группировка функционала**: объединение взаимосвязанных типов в единую логическую сущность (например, библиотечные классы для статистического анализа целесообразно поместить в один пакет).
    
      
    
2. **Разделение пространств имён**: пакеты предотвращают конфликты идентификаторов. Имя класса должно быть уникальным только в рамках своего пакета, благодаря чему классы разных авторов могут иметь одинаковые имена и не конфликтовать друг с другом.
    
      
    
3. **Разграничение прав доступа**: код внутри пакета может взаимодействовать на особых правах доступа, недоступных внешнему коду.
    
      
    
4. **Иерархическая организация**: благодаря возможности вложения пакетов создаются прозрачные и масштабируемые иерархии модулей.
    
      
    

### 2. Объявление пакета (`package`)

Чтобы объявить принадлежность классов или интерфейсов исходного файла к конкретному пакету, в самом начале текста программы помещается специальная инструкция:

  

Java

```
package mypackage;
```

Правила оформления:

  

- Инструкция `package` должна быть первой строкой кода в файле (модуле компиляции) до объявлений классов или интерфейсов.
    
      
    
- В пределах одного файла допускается объявить **только один** пакет.
    
      
    
- **Анонимный (безымянный) пакет (unnamed package)**: если тип явным образом не объявлен в составе пакета, он автоматически относится к анонимному пакету. Такой подход допустим для простых учебных или изолированных программ, но весь повторно используемый код библиотек и приложений обязательно должен быть оформлен в именованные пакеты.
    
      
    

### 3. Полные и простые имена типов

Наименование любого типа, входящего в пакет, неявно дополняется префиксом имени этого пакета:

  

- **Полное имя типа**: имя типа с префиксом пакета, разделённое точкой (например, полным именем класса `String` является `java.lang.String`, а класса `Body` из пакета `skybodies` — `skybodies.Body`).
    
      
    
- **Простое имя типа**: идентификатор самого типа без указания имени пакета (например, `String`, `Body`).
    
      
    

### 4. Механизм импортирования (`import`)

Если в программе требуется обратиться к классам из другого пакета, можно использовать их полные имена либо воспользоваться инструкцией `import` в верхней части файла (после директивы `package`, но до классов):

  

1. **Импорт единственного типа (single type import)**: явно подключает один класс/интерфейс:
    
      
    
    Java
    
    ```
    import java.util.List;
    ```
    
2. **Импорт по требованию (import on demand)**: использует символ `*` для доступа ко всем типам указанного пакета:
    
      
    
    Java
    
    ```
    import java.util.*;
    ```
    

Особенности импорта в Java:

  

- Механизм импорта **не копирует** исходный или скомпилированный байт-код, а лишь указывает компилятору, где искать типы, заданные простыми именами.
    
      
    
- Классы текущего пакета импортируются **неявно** и всегда доступны напрямую по простым именам.
    
      
    
- Пакет `java.lang`, содержащий ключевые типы платформы, **всегда импортируется по умолчанию**.
    
      
    

### 5. Общепринятые соглашения по именованию пакетов

В соответствии со стандартами оформления кода Java:

  

- Имена пакетов записываются **исключительно строчными (маленькими) буквами**.
    
      
    
- Пакеты, начинающиеся с `java.` — базовые системные пакеты языка (например, `java.lang`, `java.util`, `java.io`).
    
      
    
- Пакеты, начинающиеся с `javax.` — стандартные расширения языка (например, `javax.swing`, `javax.xml`).
    
      
    
- Пакеты сторонних компаний и организаций принято именовать по доменному имени организации в обратном порядке (например, консорциум W3C с сайтом `www.w3c.org` именует свой пакет как `org.w3c.dom`).
    
      
    

### 6. Взаимосвязь пакетов и уровней доступа

Пакет является границей для одного из фундаментальных уровней видимости:

  

- **Пакетный доступ (package-private / default)**: если член класса (поле, конструктор, метод) или сам класс объявлен без явного модификатора доступа, он виден только внутри своего класса и другим классам, находящимся в **том же самом пакете**.
    
      
    
- **Защищённый доступ (`protected`)**: доступен внутри своего класса, классам того же пакета, а также классам-наследникам (даже если они находятся в других пакетах).
    
      
    
- Класс, не помеченный модификатором `public`, невидим для кода за пределами своего пакета.

## 8. Пространства имен.

В языке Java задача управления именами элементов программы (типов, переменных, полей, методов и др.) решается с помощью двух взаимосвязанных механизмов: разделения на **пространства имён (namespaces)** и разграничения видимости имён посредством **контекстов**.

  

### 1. Шесть пространств имён в Java

Для элементов различных категорий в Java предусмотрены независимые пространства имён. Всего их выделяется шесть:

  

- **Пакеты**;
    
      
    
- **Типы** (классы и интерфейсы);
    
      
    
- **Поля**;
    
      
    
- **Методы**;
    
      
    
- **Локальные переменные и параметры**;
    
      
    
- **Метки** (используемые в конструкциях `break` и `continue`).
    
      
    

Разделение пространств имён означает, что компилятор различает сущности не только по символьному идентификатору, но и по синтаксической роли. Благодаря этому в одном и том же классе поле и метод могут иметь одинаковые имена без возникновения коллизий.

  

В качестве наглядной демонстрации независимости пространств имён в учебном курсе приводится синтаксически корректный пример, где один и тот же идентификатор `Reuse` одновременно задействован во всех шести пространствах:

  

Java

```
package Reuse; // Пространство пакетов

class Reuse { // Пространство типов
    Reuse Reuse (Reuse Reuse) { // Тип возвращаемого значения, имя метода, тип параметра, имя параметра
        Reuse: // Пространство меток
        for(;;) {
            if (Reuse.Reuse(Reuse) == Reuse)
                break Reuse; // Переход по метке
        }
        return Reuse;
    }
}
```

Несмотря на то что компилятор успешно разбирает этот код, на практике злоупотреблять совпадением имён не следует, чтобы не ухудшать читаемость программы.

  

### 2. Пакеты как средство организации пространства имён типов

На глобальном уровне программы пространство имён типов разделяется с помощью **пакетов**.

  

- Пакеты позволяют избежать конфликтов идентификаторов, если разные разработчики дали своим классам одинаковые наименования.
    
      
    
- В рамках пакета имя класса или интерфейса должно быть уникальным, однако в разных пакетах могут сосуществовать классы с одинаковыми простыми именами.
    
      
    
- Полное имя типа формируется как префикс имени пакета, отделённый точкой от имени класса (например, `java.lang.String`), что исключает неоднозначность при обращении к классам.
    
      
    

### 3. Контексты и сокрытие имён

Внутри одного пространства имён управление видимостью осуществляется контекстами:

  

- **Контекст объявления**: каждое имя действует в пределах своего контекста. Например, контекстом параметра метода является тело этого метода, контекстом локальной переменной — блок, в котором она объявлена, а контекстом переменной цикла `for` — заголовок и тело данного цикла.
    
      
    
- **Вложенность**: код внутреннего контекста имеет доступ к именам внешнего контекста (например, из тела цикла доступны локальные переменные метода).
    
      
    
- **Сокрытие (перекрытие) имён**:
    
      
    - Имена из внешних контекстов могут скрываться внутренними. В частности, локальная переменная или параметр метода перекрывают поле класса с тем же именем (в таком случае для явного доступа к полю объекта используется ссылка `this.имяПоля`).
        
          
        
    - Перекрытие имён **запрещено** внутри одного блока кода: нельзя объявить локальную переменную с тем же именем, что и параметр метода, или повторно объявить переменную с уже занятым именем во вложенном блоке.

## 9. Модуль компиляции.

### Понятие модуля компиляции

**Модуль компиляции (compilation unit)** — это исходный текстовый файл с расширением `.java`, представляющий собой единичную порцию входных данных для компилятора Java.

Исходный файл содержит исходный код программы, включающий одно или несколько описаний классов и интерфейсов.

### Структура модуля компиляции

Текст в модуле компиляции организуется в строгом порядке и состоит из трёх основных разделов:

1. **Объявление пакета (`package`)**:
    
    - Если файл принадлежит определённому пакету, объявление (например, `package mypackage;`) должно располагаться в самом начале файла, до любых объявлений классов или интерфейсов.
        
    - В пределах одного файла допускается указать только одно объявление `package`.
        
    - Если инструкция `package` не указана вовсе, компилятор помещает описанные в файле типы в так называемый _анонимный (безымянный, unnamed) пакет_.
        
2. **Выражения импортирования (`import`)**:
    
    - Размещаются следом за объявлением пакета (перед объявлениями классов и интерфейсов).
        
    - Служат для того, чтобы в коде можно было обращаться к типам из других пакетов по их простым именам, а не полным.
        
    - Могут использоваться в виде _импорта единственного типа_ (например, `import java.util.List;`) или _импорта по требованию_ (например, `import java.util.*;`).
        
    - Пакет `java.lang` всегда неявно импортируется по умолчанию, указывать его отдельно не требуется.
        
3. **Объявления верхнего уровня (типов)**:
    
    - Описания классов (`class`) и интерфейсов (`interface`).
        

### Важные правила и особенности компиляции

- **Ограничение на открытые (public) классы:** В одном модуле компиляции может находиться **не более одного** класса или интерфейса, объявленного с модификатором `public`. При этом имя файла обязано в точности совпадать с именем этого открытого класса (с учётом регистра символов).
    
- **Непубличные классы:** Количество классов без модификатора `public` (доступных на уровне пакета) в одном файле может быть произвольным.
    
- **Результат компиляции:** Хотя на входе компилятор получает один исходный файл `.java`, на выходе для _каждого_ описанного внутри класса (как открытого, так и непубличного) создаётся свой собственный отдельный файл байт-кода с расширением `.class` и именем, соответствующим названию конкретного класса.
## 10. Поля.
### 1. Понятие и назначение полей

**Поля (fields)** — это переменные, объявленные в классе, которые в совокупности определяют состояние класса или конкретного объекта (экземпляра).

Каждый создаваемый объект (экземпляр) класса, как правило, обладает собственными «личными» копиями полей, то есть индивидуальным состоянием. Такие поля также называют **переменными экземпляра**. Изменение значения поля одного объекта не влияет на одноимённые поля других объектов того же класса.

### 2. Структура объявления поля

Конструкция объявления поля включает в себя:

1. Необязательные **модификаторы** (модификаторы доступа, `static`, `final`, `transient`, `volatile`).
    
2. **Тип данных** (простой или ссылочный).
    
3. **Идентификатор** (имя поля).
    
4. Необязательное **выражение инициализации**.
    

Java

```
public class Body {
    public long idNum;
    public String name = "<Без имени>";
    public Body orbits = null;
    private static long nextId = 0;
}
```

(Пример взят из учебного пособия)

### 3. Значения полей по умолчанию

Если поле класса не инициализировано явным образом, исполняющая система автоматически присваивает ему значение по умолчанию в зависимости от типа:

- `boolean`: `false`
    
- `char`: `\u0000`
    
- `byte`, `short`, `int`, `long`: `0`
    
- `float`: `0.0f`
    
- `double`: `0.0`
    
- Ссылочные типы (любые объекты, массивы): `null` (означает, что ссылка ни на что не указывает)
    

### 4. Модификаторы полей

#### А. Модификаторы доступа

- **`private`** — поле доступно только внутри контекста самого класса.
    
- **По умолчанию (package-private)** — модификатор не указывается; поле доступно внутри текущего класса и всех классов того же пакета.
    
- **`protected`** — доступно внутри своего класса, классов того же пакета и классов-наследников (в том числе в других пакетах).
    
- **`public`** — открыто для доступа отовсюду, где доступен сам класс.
    

> **Важно:** контроль доступа осуществляется на уровне **класса**, а не конкретного объекта. Это означает, что метод класса может напрямую обратиться к `private`-полям любого другого объекта этого же класса (например, если ссылка на него передана в метод в качестве аргумента).

#### Б. Модификатор `static` (поля класса)

- Поле с модификатором `static` существует в **единственном экземпляре** для всего класса, независимо от того, сколько объектов было создано (и создавались ли они вообще).
    
- Извне класса к статическому полю принято обращаться через имя класса: `Body.nextId`, а не через ссылку на экземпляр.
    

#### В. Модификатор `final` (константы)

- Значение поля с модификатором `final` после инициализации **не может быть изменено**; повторное присваивание вызовет ошибку компиляции.
    
- Если поле объявлено как `final`, но не инициализировано при объявлении, оно называется **blank final**. Такое поле обязано быть инициализировано ровно один раз:
    
    - в блоке статической инициализации (если поле `static`);
        
    - либо в конструкторах / блоках инициализации экземпляра (если поле нестатическое).
        
- Константы класса обычно объявляются комбинацией `static final` (например, `public static final double PI = 3.14159;`).
    

#### Г. Модификаторы `transient` и `volatile`

- `transient` — исключает поле из процесса сериализации (сохранения состояния объекта в поток байт).
    
- `volatile` — используется в многопоточном программировании для синхронизации доступа и видимости переменной между потоками.
    
- _Ограничение:_ модификаторы `final` и `volatile` **не могут** применяться одновременно.
    

### 5. Инициализация полей

Инициализировать поля можно следующими способами:

1. **Явно при объявлении** (константой, выражением или результатом вызова метода, не выбрасывающего непроверяемые/объявляемые исключения).
    
2. **В блоках инициализации экземпляра** `{ ... }` — отрабатывают при создании каждого объекта до вызова тела конструктора.
    
3. **В статических блоках инициализации** `static { ... }` — отрабатывают один раз при загрузке класса в JVM для сложных вычислений над статическими полями.
    
4. **В конструкторах**.
    

### 6. Сокрытие полей (Field Hiding)

В отличие от методов, **поля не переопределяются при наследовании, а скрываются**:

- Если класс-наследник объявляет поле с таким же именем, как в базовом классе, поле базового класса продолжает существовать, но становится скрытым.
    
- К какому полю произойдёт обращение по имени, зависит от **объявленного типа ссылки**, а не от фактического объекта во время выполнения:
    
    Java
    
    ```
    SuperClass ref = new SubClass();
    System.out.println(ref.value); // обратится к SuperClass.value!
    ```
    
- Для явного обращения к полю родительского класса из дочернего используется ключевое слово `super.fieldName` или приведение типа ссылки `((SuperClass) this).fieldName`.

## 10. Методы
### 1. Понятие и структура метода

В языке Java класс объединяет данные и операции над ними. Методы класса — это именованные фрагменты исполняемого программного кода, которые определяют поведение объектов и манипулируют их состоянием.

  

Объявление метода состоит из двух основных частей:

  

1. **Заголовок метода**.
    
      
    
2. **Тело метода** — набор выражений и инструкций, заключённый в фигурные скобки `{}`.
    
      
    

В общем виде заголовок метода включает в себя:

  

- **Модификаторы** (необязательный элемент).
    
      
    
- **Тип возвращаемого значения** (обязательный элемент; если метод не возвращает значение, указывается ключевое слово `void`).
    
      
    
- **Сигнатуру метода** — идентификатор (имя) метода и список типов параметров в круглых скобках (список может быть пустым).
    
      
    
- **Предложение `throws`** — список объявляемых классов исключений, которые метод может выбросить в процессе своего выполнения (необязательный элемент).
    
      
    

Обязательными составляющими любого объявления являются сигнатура и тип возвращаемого значения.

  

### 2. Модификаторы методов

В объявлении метода могут использоваться следующие категории модификаторов:

  

- **Модификаторы доступа**: `private`, `protected`, `public`, а также пакетный уровень доступа (default, когда модификатор опущен).
    
      
    
- **`static`**: объявляет статический метод (метод класса), принадлежащий классу в целом, а не конкретному объекту.
    
      
    
- **`abstract`**: метод не содержит реализации (тело заменяется точкой с запятой `;`) и подлежит реализации в производных классах. Сам класс при этом также обязан быть абстрактным.
    
      
    
- **`final`**: запрещает возможность переопределения метода в классах-наследниках.
    
      
    
- **`synchronized`**: используется для синхронизации потоков при параллельном выполнении программы.
    
      
    
- **`native`**: указывает, что тело метода реализовано на платформенно-зависимом языке (например, C или C++) с использованием интерфейса JNI.
    
      
    
- **`strictfp`**: обеспечивает единообразное и строгое выполнение операций с плавающей запятой на различных аппаратных платформах.
    
      
    

Метод `abstract` не может комбинироваться с модификаторами `static`, `final`, `synchronized`, `native` или `strictfp`.

  

### 3. Вызов методов, передача параметров и возврат значений

- **Вызов метода**: для вызова метода экземпляра используется ссылка на объект, оператор точки и имя метода со списком аргументов: `reference.method(arguments);`. Для вызова статического метода принято указывать имя самого класса: `ClassName.method(arguments);`.
    
      
    
- **Передача параметров**: в Java аргументы в методы передаются **только по значению** (pass-by-value).
    
      
    - Для простых (примитивных) типов метод получает локальную копию значения, поэтому любые изменения этой переменной внутри метода не влияют на исходную переменную в вызывающем коде.
        
          
        
    - Для ссылочных типов по значению передаётся сама ссылка (копия ссылки). Это означает, что переприсваивание ссылки внутри метода не изменит внешнюю ссылку, однако изменение внутренних полей объекта по этой ссылке изменит состояние исходного объекта.
        
          
        
    - Параметры методов могут быть помечены как `final`, что запрещает изменение их значений внутри метода.
        
          
        
- **Завершение работы и возврат значений**: управление возвращается в вызывающий код в одном из трёх случаев:
    
      
    - выполнение инструкции `return`;
        
          
        
    - достижение конца тела метода (допустимо только для методов типа `void`);
        
          
        
    - генерация (выбрасывание) исключения.
        
          
        

### 4. Перегрузка методов (Overloading)

В одном классе можно объявить несколько методов с одинаковым именем, если они различаются сигнатурами — количеством параметров или их типами. Такие методы называются перегруженными. Тип возвращаемого значения и секция `throws` не входят в сигнатуру метода и не могут служить основанием для перегрузки.

  

### 5. Метод `main`

Метод `main` является входной точкой (точкой старта) любого автономного консольного приложения на Java. При запуске приложения исполняющая система (JVM) загружает указанный класс, находит в нём метод `main` и передаёт ему управление.

  

#### Синтаксис метода `main`:

Java

```
public static void main(String[] args) {
    // инструкции тела метода
}
```

  

  

#### Назначение каждого элемента объявления

:

  

  

- **`public`**: метод объявляется общедоступным, чтобы внешняя среда исполнения (виртуальная машина JVM) могла беспрепятственно вызвать его.
    
      
    
- **`static`**: метод объявляется статическим, чтобы виртуальная машина могла запустить его без необходимости предварительного создания объекта данного класса.
    
      
    
- **`void`**: метод не возвращает никакого значения вызывающей операционной среде.
    
      
    
- **`main`**: обязательное стандартное имя метода, зарезервированное спецификацией в качестве стартовой точки программы.
    
      
    
- **`String[] args`** (допустима также запись `String args[]`): единственный обязательный параметр метода, представляющий собой ссылку на массив строк (`String`). Через этот массив программе передаются аргументы командной строки, задаваемые пользователем при запуске.
    
      
    

#### Особенности работы с `main`:

- **Получение аргументов**: если программа запускается из командной строки в виде:
    
      
    
    Bash
    
    ```
    java Echo Привет студенты
    ```
    
    то JVM загрузит класс `Echo`, вызовет его метод `main` и передаст массив `args`, содержащий элементы `"Привет"` (индекс 0) и `"студенты"` (индекс 1).
    
      
    
- **Несколько методов `main`**: в проекте или приложении метод `main` может быть объявлен сразу в нескольких классах. Однако при конкретном запуске будет выполнен только тот метод `main`, который принадлежит классу, явно переданному в параметрах запуска виртуальной машине Java.
